# 전차(탱크) 모형 조립·검사 라인 PRD

2026-09-29 · 정성욱

> 표기: "공정 n"은 `process-table.md`의 공정 번호(1~18)입니다. 작업 위치는 ST1·ST2·ST3(ST1 = 하부 차체 투입·파워팩 조립, ST2 = 포탑 조립·용접 모션, ST3 = 최종 검증·분류)이고, 로봇은 로봇1·로봇2·로봇3(각각 ST1·ST2·ST3 담당)입니다. P0-n·P1-n은 구현 단계(P0 = 핵심, P1 = 추가) 기능 번호입니다.

## 1. Why - 목적

- 문제
  - 협동로봇, PLC, 비전, 임베디드, 웹 트윈을 하나의 공정으로 통합해 보여 줄 팀 프로젝트가 필요함
  - 조립·검사·판정이 하나의 데이터 흐름으로 이어지는 사례가 필요함
- 목표
  - P0: 전차(탱크) 모형 단일 기종 라인 (Indy7 3대, 컨베이어 5구간, PLC Q03UDV, Python 게이트웨이, 비전, 웹 트윈)
  - P0: 첨부 공정 계획 중 파워팩 장착(로봇1), 포탑 조립과 용접 모션(로봇2), ST3 최종 검증과 합격/불합격 분류(로봇3), 결과 기록 (나머지 공정은 P1 또는 추후)
  - P1: PCB 도입 후 BLE 기능 검사(자체 테스트)와 조기 차단, 버퍼 1차 검증, 기종 A/B 혼류 등 확장
  - 완성 전차 3대 이하를 재사용 가능한 구조로 설계
- 성공 기준 (KPI, 목표값은 제안이며 첫 측정 후 팀 합의로 확정)
  - P0
    - K1 조립: 로봇1 파워팩 조립, 로봇2 포탑 조립 각 95% 이상 (각 30회 이상)
    - K2 최종 검증: 누락·방향·위치 불량 검출 90% 이상, 정상품 오검출 5% 이하 (각 30장 이상)
    - K3 지연: 작업 지시(REQ)에서 로봇 BUSY까지 1초 이하, 트윈 반영 1초 이하 (95번째 백분위, 가정)
    - K4 조기 차단: 조립 실패(ERR) 또는 주입 NG 시 이후 위치의 작업 생략 100%
    - K5 사이클 타임: 병목 구간(예상: ST2) 식별과 개선 전후 비교 (수치 미정)
    - K6 용접 모션: 교시 경로 완주 95% 이상 (30회 이상, 가정)
    - 보조: 연속 30사이클에 사람 개입(팔레트 배치 제외) 3회 이하, 인터록 위반 0건 (시나리오 20개)
  - P1 (PCB 도입 후)
    - K7 기능 불량 검출: 주입 불량(LED 개방, 저전압) 검출 100% (각 10회 이상)
    - K8 BLE: 패킷 손실 5% 이하 (1시간), 결과의 PLC 기록 지연 3초 이하 (95번째 백분위)
  - 측정: 자석 체결의 쉬운 분리로 사람이 되돌리며 반복 시행, 결과는 시행 횟수(N)와 함께 표기
- 제약
  - 기간 6주, 인원 11명 (PLC 4, PC 4, 디자인 3)
  - PCB는 P1로 이관: P0의 Powerpack 모듈은 기능 없는 더미, 공정 11(Function Test)은 P1에서 구현
  - 로봇 툴: 로봇2는 파지 툴 (포탑 조립과 용접 모션), 로봇1·로봇3는 미정 (P0-0 시편 검증 후 확정)
  - 로봇 컨트롤박스 3개(192.168.3.2 ~ .4)는 서로 알지 못함 → 인터록은 PLC 또는 게이트웨이가 담당
  - 접착제 도포, 로트 마킹, QR 표식, 실제 용접은 제외 (위치 결정핀 + 자석 체결, 용접은 교시한 경로를 따라 움직이는 모사)
  - 전차 크기(가정): 길이 약 165 × 너비 약 110 × 높이 60~70 mm (궤도 포함), 하부 차체에 파워팩과 포탑을 결합, 포탑은 서브라인에서 선행 조립 (상부·측면 구조물은 P0에서 제외)
  - 컨베이어 폭 100 mm, 팔레트 폭 약 120 mm (가정)
  - 3D 프린터 사용 가능, 재질 미정
- 범위 밖 (P1 또는 추후)
  - 재활용, 분해, 상부·측면 구조물 조립(공정 2), 작업자 용접 경로 표시·카메라 경로 검출·궤적 생성·경로 오차 검사·PASS/RETRY(공정 12~14·16·17)
  - 확장 기능 전체 (4장 P1 참조)

## 2. Who - 타깃 사용자

- 팀 개발자 (11명)
  - 니즈: 모듈별 인터페이스 명세, 디버깅 로그, 단독 테스트 가능한 구조
  - PLC팀 4명 (가정: 팀 합의 전 제안)
    - PLC-A 2명: P0-1·2·4·5·13, P1-4·13
    - PLC-B 2명: P0-3·6·7·8·12
  - PC팀 4명
    - 게이트웨이 2명: P0-10, P1-2·3
    - 비전 1명: P0-11, P1-9·13
    - 웹 트윈 1명: P0-14, P1-5
  - 디자인팀 3명
    - 전차 기구 1명: P0-7 체결 설계, P1-12
    - 팔레트·모듈 1명: P0-9, 팔레트, 트레이, 로봇 툴 플랜지, 용접 모형 툴
    - 3D 모델·자료 1명: 트윈용 GLB 모델, 발표 자료
  - 미정: P1-1 PCB 담당 (제안: PC팀 게이트웨이 중 1명), P1-6·10은 디자인팀 + PCB 담당
  - 인터페이스: PLC팀↔PC팀은 MC 프로토콜 비트 맵, 디자인팀↔PLC-B는 로봇 툴·팔레트 치수
- 라인 운영자 (시연·운전)
  - 니즈: 시작, 일시정지, 리셋, 상태 확인, NG 원인 확인, 팔레트 배치
- 재작업 담당자 (P1)
  - 니즈: NG 원인 확인, 수정 후 재투입
- 포트폴리오 열람자 (면접관, 평가자)
  - 니즈: 동작 영상, 웹 트윈, KPI 결과를 빠르게 확인

## 3. User Flow

- 컨베이어: ST1 → 버퍼 → ST2 → ST3 → 잉여 (5구간, 구간별 모터). 잉여 구간은 팔레트 보관창고
- 정상 흐름 (P0)
  1. 운영자가 시작 위치에 팔레트를 배치하고 시작 버튼을 눌러 가동. 제품 ID는 부여하지 않고 팔레트 단위로 추적
  2. 팔레트가 ST1 위치에 도착하면 하부 차체(바퀴 포함)를 팔레트 위에 올림 (공정 1, 수행 주체 가정: 로봇1)
  3. ST1: 로봇1이 파워팩을 차체 안으로 조립 (공정 6)
      - 실패 → ERR, NG 기록, 이후 작업 생략 (팔레트는 ST3까지 이동만 하고 불합격 트레이로 분류)
  4. 완료되면 팔레트가 버퍼로 이동해 대기하다 ST2가 비면 이송 (버퍼 1차 검증은 P1-13)
  5. ST2: 로봇2가 포탑을 조립한 뒤 파지 툴로 용접 모션을 실행 (공정 9·15)
  6. ST3로 이동해 비전이 최종 검증하고, PLC가 합격/불합격 확정 (공정 10)
  7. 로봇3가 합격은 합격 트레이로, 불합격은 다른 트레이로 분류 (이송 주체 가정: 로봇3)
  8. 팔레트는 컨베이어를 따라 계속 이동해 잉여 구간의 보관창고에 보관 (공정 18)
  9. 웹 트윈이 전 과정을 실시간 표시
- 기능 검사 (P1, PCB 도입 후 추가)
  1. ST1: 파워팩 장착 직후 자석이 홀센서를 트리거 → PCB 자체 테스트 → 광고 → 게이트웨이 수신
      - 2초 내 수신 실패 → 재시도, 초과 시 NG → ST2 작업 생략, ST3에서 불합격 트레이로
  2. ST3: 최종 조립 검사와 함께 BLE 생존 확인, PLC가 두 결과로 OK/NG 확정 (포탑 회전 시험은 P1-10)
- 불량 재작업 (P1)
  1. 불합격 트레이의 전차를 작업자가 수거
  2. 재작업 담당자가 원인(모듈, 체결, 외관) 확인 후 수정
  3. 재투입 (재진입 지점 미정) → 재검사 → OK/NG 확정, 재작업 횟수 기록
      - 한도 초과 → 폐기 트레이 (한도 미정)

## 4. 기능 요구사항

### P0 - 핵심 기능

- P0-0 1주차 리스크 검증 (구현 착수 전, 결과에 따라 치수·툴 설계 확정)
    - 로봇 툴 시편: 로봇2 파지 툴로 포탑 Ass'y를 집어 결합하고, 용접 모형 툴을 든 채 교시 경로를 완주 (낙하 없음, 위치 이탈 확인). 로봇1·로봇3는 후보 툴(석션, 그리퍼 등)로 파워팩 모듈과 전차를 들어 이송 (디자인팀 + PLC-B)
    - 팔레트 정지 반복 정밀도: 30회 정지시켜 편차 ±1 mm 이내 확인 (PLC-A)
    - 팔레트 돌출 간섭: 폭 약 120 mm가 옆 가이드와 간섭 없는지 확인, 안 되면 A안(팔레트 95 mm, 모듈 100×60 mm)으로 전환 (디자인팀)
    - 무게 측정: 전차 300 g 이하 (디자인팀)
    - PLC↔PC 비트 맵 확정: 양쪽이 같은 표로 단독 테스트 가능 (PLC 1명 + PC 1명)
    - 기록: 시행 횟수 N·성공·실패 원인을 표로 남김 (K1의 개선 전 값)
    - 미정: PCB 담당자, 로봇1·로봇3 툴, 하부 차체를 올리는 주체(가정: 로봇1), 삽입 성공 감지 방법, 팔레트 식별 방식, 용접 모형 툴 형태
- P0-1 팔레트 트래킹 (PLC) · 담당: PLC-A
    - 동작: 제품 ID 없이 위치별 레코드 `{module_id, turret_id, step, ng}`를 팔레트 이동에 맞춰 다음 구간으로 이월 (기종 필드는 P1-12에서 추가)
    - 팔레트: 폭 약 120 mm로 벨트(100 mm) 양옆 돌출(가정), 전차 둥지와 위치 결정 홈. 식별 방식·가이드 간섭은 미정
    - 완료 조건: 라인을 지나도 레코드 일치
- P0-2 컨베이어 이송·정지 (PLC) · 담당: PLC-A
    - 동작: 시작 버튼으로 가동, 5구간이 구간별 모터로 독립 동작, 다음 구간이 비었을 때만 출발. ST3 점유 중에는 ST2 대기 (ST3 앞 버퍼 없음). 팔레트는 마지막에 잉여 구간(보관창고)으로 이동해 보관
    - 신호: `CV1_RUN` ~ `CV5_RUN`, `CV#_STATE` (EMPTY, ARRIVING, HOLD, DEPARTING), 입력은 구간별 센서와 로봇 DONE
    - 완료 조건: 정지 위치 반복 오차가 삽입 허용 범위 안 (수치 미정, P0-6 참조)
    - 리스크: ST2 사이클(포탑 조립, 용접 모션)이 가장 길어 병목이 될 수 있음. K5로 측정해 버퍼 위치 재검토
- P0-3 로봇 작업 핸드셰이크 · 담당: PLC-B (게이트웨이 측은 PC팀)
    - 동작: PLC가 REQ를 올리면 게이트웨이가 Indy7에 IndyDCP3로 지시, 응답은 BUSY / DONE / ERR
    - 작업 코드: `ROBOT1_HULL_PLACE`, `ROBOT1_POWERPACK_MOUNT`+슬롯, `ROBOT2_TURRET_MATE`+슬롯, `ROBOT2_WELD_MOTION`, `ROBOT3_SORT`+PASS/FAIL
    - 완료 조건: 로봇 3대 각각 REQ→BUSY→DONE과 ERR 경로 동작
- P0-4 인터록과 NG 건너뛰기 (PLC) · 담당: PLC-A
    - 동작: 로봇 간 간섭 구역 플래그 관리, `ng` 팔레트는 이후 공정 작업 거부 (ST3의 불합격 분류는 수행)
    - 완료 조건: 간섭 구역에 두 로봇이 동시에 들어가지 않음, K4 달성
    - 미정: NG 주입 방법 (가정: 게이트웨이 시험 명령)
- P0-5 비상정지 (하드웨어, 가정) · 담당: PLC-A
    - 동작: 하드웨어 버튼으로 로봇과 컨베이어 정지 (음성 명령으로 대체하지 않음)
    - 완료 조건: 소프트웨어 상태와 무관하게 동작
- P0-6 로봇1 하부 차체 투입과 파워팩 조립 (ST1, 툴 미정, 공정 1·6) · 담당: PLC-B (툴 플랜지는 디자인팀)
    - 동작: 팔레트 도착 시 하부 차체(바퀴 포함)를 팔레트 둥지 위에 올리고(가정: 로봇1, 작업자 수동 투입도 가능), 트레이 슬롯 k(1~3)의 120×80 mm 파워팩 모듈(P0는 더미)을 집어 차체 후방 Bay의 123×83 mm 포켓에 삽입. 모듈 ID는 슬롯에 사전 등록
    - 완료 조건: 포켓 간극 한쪽 1.5 mm, 챔퍼 1.5 mm 사양에서 위치 허용오차 ±1 mm, 성공률 K1
    - 전제(석션 채택 시): 모듈 상단에 평평하고 기밀한 흡착면 (3D 프린트 표면 밀봉)
    - 검증: P0-0 툴 시편으로 반복 정밀도를 측정해 툴 확정
    - 리스크: 팔레트와 로봇 사이 위치 정밀도 (대응: 깔때기형 안착, 정밀 인덱싱, 비전 보정은 쓰지 않음)
    - 미정: 삽입 성공 감지 방법 (후보: 석션 압력, 로봇 하강 위치, 팔레트 센서)
- P0-7 로봇2 포탑 조립 (ST2, 파지 툴, 공정 9) · 담당: PLC-B (체결 설계는 디자인팀)
    - 동작: 서브라인에서 조립한 포탑 Ass'y를 파지 툴로 집어 차체 상부의 포탑 링 위에 위치 결정핀을 맞춰 내려놓고 자석 체결
    - 완료 조건: 성공률 K1. 시편으로 핀 끝 안내 범위(목표 1~2 mm), 반복 체결·분리, 유지력 검증. 마주 보는 자석은 반대 극. 포탑 회전은 P1-10에서 확장
    - 미정: 포탑 파지 위치 (포신을 피한 면)
- P0-8 로봇2 용접 모션 (ST2, 파지 툴, 공정 15) · 담당: PLC-B (모형 툴 형상은 디자인팀)
    - 동작: 포탑 결합 후 로봇2가 파지 툴로 용접 모형 툴(마커 등)을 들고 사전 교시한 경로를 따라 이동해 용접을 모사. 실제 용접, 작업자 경로 표시, 카메라 경로 검출, 경로 오차 검사는 없음
    - 완료 조건: 교시 경로를 접촉·간섭 없이 완주, 성공률 K6, 사이클 타임 기록
    - 미정: 용접 모형 툴 형상과 파지 방식(거치대에서 집기 또는 상시 파지), 교시 경로 위치(포탑 링 이음선 등), 마커로 선을 남길지 여부
- P0-9 서브라인 선행조립과 더미 모듈 (공정 4·7) · 담당: 디자인팀 (팔레트·모듈), 조립은 작업자
    - 동작: 작업자가 Engine·Transmission·Cooling 구성품을 결합해 120×80 mm 파워팩 모듈로, 포탑 몸체와 포신을 결합해 포탑 Ass'y로 만들어 트레이 슬롯에 놓음. P0의 파워팩은 무게만 맞춘 기능 없는 더미 (3D 프린트 케이스)
    - 완료 조건: 삽입 사양(P0-6) 만족, P1의 PCB 모듈과 외형·파지면 호환, 슬롯별 모듈 ID·포탑 ID 사전 등록
    - 미정: 더미 무게 (PCB와 배터리 포함 실측 후), 구성품을 블록 3개로 나눌지 단일 더미로 할지
- P0-10 게이트웨이 (Python) · 담당: PC팀 (게이트웨이)
    - 동작: pymcprotocol로 PLC, IndyDCP3로 로봇, 웹에 이벤트 전달 (BLE 수신은 P1-2)
    - 구조: PLC·웹은 asyncio, 로봇당 스레드 1개와 큐, PLC 기록은 단일 태스크
    - 완료 조건: 하트비트로 PLC가 게이트웨이 정지를 감지, 작업 지시 지연 K3
- P0-11 비전 최종 검증 (ST3 전용, 고정 카메라 1대, 공정 10) · 담당: PC팀 (비전)
    - 동작: 고정 노출로 파워팩 장착 상태, 포탑 정렬·이음 간격·기울기, 부품 누락·방향을 규칙 기반으로 판정. ST1·ST2에는 카메라 없음 (공정 3·5·8의 중간 검사는 이 검사로 통합, 버퍼 1차 검증은 P1-13)
    - 완료 조건: 검출률·오검출률 K2. QR과 LED 점등 판정, AI 모델은 P0에서 제외
- P0-12 로봇3 합격/불합격 분류 (ST3, 툴 미정) · 담당: PLC-B
    - 동작: PLC가 확정한 결과에 따라 로봇3가 전차를 집어 합격 트레이 또는 불합격 트레이로 이송 (이송 주체 로봇3는 가정). ST1·ST2에서 작업이 생략된 팔레트도 ST3에서 불합격 트레이로 분류
    - 완료 조건: 전차 무게에서 파지 유지, 이송 중 낙하 없음, 판정과 트레이가 일치
    - 미정: 로봇3 툴, 트레이 위치·구획
- P0-13 최종 판정과 기록 (공정 18) · 담당: PLC-A (로그 수집은 PC팀)
    - 동작: 로봇1·로봇2 결과(ERR 여부)와 ST3 최종 검증으로 합격/불합격을 확정하고, 결과를 가동 순번(가정)과 시각과 함께 기록. 제품 ID는 없음
    - 출력: `ng`, NG 사유, 시각, 가동 순번 (기능 검사 결과는 P1-3에서 추가)
    - 완료 조건: 모든 가동에 판정과 사유가 남음, 사이클 타임 로그로 K5 측정
    - 미정: 보관창고 수용 팔레트 수와 정지 위치
- P0-14 웹 모니터링 트윈 · 담당: PC팀 (트윈), 디자인팀 (GLB 모델)
    - 동작: FastAPI + WebSocket, three.js + Blender GLB로 컨베이어 5구간과 위치 3개의 팔레트·로봇·판정 표시
    - 완료 조건: 현장 상태와 화면 상태가 일치, 반영 지연 K3

### P1 - 추가 기능

- P1-1 구동 모듈 PCB (1종 공통) · 담당: 미정
    - 동작: BLE MCU가 상시 광고(약 1초), 홀센서로 자체 테스트 시작. P0의 더미 모듈을 같은 외형의 PCB 모듈로 교체
    - 구성: BLE MCU(내장 안테나 모듈), 3.3V LDO, P-MOSFET 역전압 보호, 스위치, LED×2, 홀센서, 션트 전류 센싱, SWD 패드, 모터 드라이버 풋프린트(미실장, 궤도 좌우 이중 채널 기준). 전원은 4×AAA NiMH(4.8 V)
    - 완료 조건: 안테나 금지 구역 확보, 배터리 광고 유지 실측, 삽입 사양(P0-6) 만족
    - 미정: 제작 방식(외주 또는 직접)과 리드타임 (6주 일정 영향 확인 필요)
- P1-2 BLE 광고와 게이트웨이 수신 · 담당: PC팀 (게이트웨이)
    - 동작: manufacturer data로 ID, mV, mA, flags, counter 전송 (연결 없음, 포맷 `<HHHBB`). 게이트웨이가 bleak로 수신·파싱해 PLC에 기록 (asyncio 태스크 추가)
    - 완료 조건: counter로 손실 감지, 2초 타임아웃과 재시도, K8 달성
- P1-3 ST1 자체 테스트와 기능 판정 (조기 차단) · 담당: PCB 담당 + PC팀 (게이트웨이), PLC-A
    - 동작: 자석을 홀센서가 감지하면 PCB가 LED 시퀀스를 실행하고 션트 전류를 측정, 결과를 광고로 전송. PLC가 P0-13 판정에 반영
    - 완료 조건: LED ON 시 전류 증가량이 기준 범위 안 (기준 미정), 자석이 없으면 미실행, K7 달성, NG 시 ST2 작업 생략 (ST3에서 불합격 분류)
    - 제약: 게이트웨이는 ST1 파워팩 장착 직후의 결과만 채택 (이후 포탑 자석의 재트리거는 무시), ST3는 BLE 광고 유무로 생존 확인
    - 검증: 포탑 자석이 홀센서를 오작동시키지 않는지 실측
    - 한계: 전류는 LED 도통만 확인, 빛이 나오는지는 외관 검사가 보완 (LED가 보이는 구조는 미정)
- P1-4 불량 재작업 반송 · 담당: PLC-A
    - 동작: 불합격 트레이의 전차를 작업자가 수정 후 다시 투입 (가정: 수동 재투입, 자동 반송 경로는 추가 검토)
    - 완료 조건: 불합격 전차가 재작업 후 재검사에서 합격 확정
    - 미정: 재진입 지점, 재작업 한도 횟수, 폐기 기준, 재작업 이력 식별 방식(제품 ID 없음)
- P1-5 재작업 이력 화면 · 담당: PC팀 (트윈)
    - 동작: 웹 트윈에 NG 사유와 재작업 회차 표시
    - 완료 조건: 팔레트별 NG 사유와 재작업 횟수 조회
- P1-6 궤도 구동 테스트 · 담당: 디자인팀 + PCB 담당
    - 동작: 모터 드라이버를 실장하고 자체 테스트에 궤도 좌우 회전 포함 (N20 기어 모터 2개 차동, 소프트 스타트, 벌크 커패시터, 팔레트 둥지의 자유 회전 여유 2~3 mm). 전제: P1-1, P1-3
    - 출력: 좌우 전류 프로파일로 개방·스톨·배터리 강하 판정, 좌우 차이로 한쪽 궤도 문제 감지
    - 한계: 슬립이나 기어 이탈은 전류로 못 잡음, 소리나 비전으로 교차 확인
- P1-7 소리 기반 이상 감지 (엣지 AI) · 담당: PC팀 (미정)
    - 동작: 자석 트리거 시점의 3초 녹음을 MFCC + 정상 소리 학습 오토인코더로 판정, SOUND_OK / SOUND_NG를 PLC에 기록. 전제: P1-6
    - 완료 조건: 오탐·미탐률 측정, 전류가 놓친 이상을 잡는 사례 제시
- P1-8 음성 명령·응답과 AI 보조 · 담당: PC팀 (미정)
    - 동작: VAD, 로컬 faster-whisper(한국어), 규칙 매칭으로 시작·일시정지·리셋·상태 명령 처리, TTS 응답. 자유 질문과 알람 원인 설명은 클라우드 LLM(tool use)을 선택 기능으로 추가. 게이트웨이가 허용 함수만 AI에 등록 (get_status, request_pause, request_resume, request_start, request_reset), 좌표·속도를 받는 함수는 없음
    - 안전: PLC에 요청 비트만 기록, 실행 여부는 PLC 인터록이 결정, 시작·리셋은 사람 확인 후 실행, 비상정지는 하드웨어 (AI 경로 없음), 모든 호출을 로그로 저장
    - 완료 조건: 신뢰도가 낮거나 목록에 없으면 미실행과 재요청 안내, 네트워크가 끊겨도 규칙 매칭 명령과 라인 동작 유지, 인터록 위반 명령은 PLC가 거부
    - 미정: 호출어 사용 여부, 마이크 위치, LLM 사용 범위, API 키 관리 (환경 변수, 저장소에 올리지 않음)
- P1-9 외관 이상 탐지 (비전 AI) · 담당: PC팀 (비전)
    - 동작: 정상 이미지만 학습한 이상 탐지 모델로 규칙이 못 잡는 스크래치·변형을 보완
    - 완료 조건: 규칙 기반과 비교한 오판·미판율 측정
- P1-10 포탑 회전 기능 시험 (공정 11) · 담당: 디자인팀 + PCB 담당
    - 동작: 포탑에 회전 구동(소형 모터)을 추가하고 자체 테스트에 포탑 회전을 포함. 전제: P1-1, P1-3, P1-6
    - 완료 조건: 미정 (회전 구동 방식과 전류 기준 검토 필요)
- P1-11 재사용·분해 · 담당: 디자인팀
    - 동작: 완성 전차 3대 이하를 분해해 모듈과 차체를 재사용
    - 완료 조건: 미정 (방식 협의 필요)
- P1-12 기종 A/B 혼류와 확장 · 담당: 디자인팀 (전차 기구) + PC팀 (비전)
    - 동작: 포탑 2종(색·형상 다름)을 3D 프린트, 하부 차체·모듈은 공통, 비전에 기종 판별 추가. 이후 A/B 외 기종과 재진입 흐름 확장
    - 완료 조건: 기종을 섞어 투입해도 오조립 없이 완성, 비전 기종 판별로 오투입 검출. P0-1 레코드에 기종 필드 추가
- P1-13 버퍼 1차 검증 (공정 3·5) · 담당: PC팀 (비전) + PLC-A
    - 동작: 버퍼 구간에 고정 카메라를 추가해 파워팩 장착 상태를 1차 검증. 불합격은 ST2·ST3 작업을 생략하고 불합격 트레이로 보냄 (조기 차단). 카메라는 버퍼와 ST3 2대가 되며 카메라별 캘리브레이션·조명을 따로 둠
    - 완료 조건: 불합격 검출률·오검출률 측정 (K2와 같은 기준), 2대 촬영 시 프레임 손실 없음
    - 미정: 불합격 팔레트를 트레이로 옮기는 주체 (ST3까지 이동해 로봇3가 분류하면 조기 차단 효과가 줄어듦)
