# 모니터링 트윈 실행 안내

전차 모형 조립·검사 라인을 3D로 보여 주는 읽기 전용 모니터다.
로봇 3대와 컨베이어 5구간의 상태를 FastAPI/WebSocket으로 받아 표시한다.

## Windows에서 시뮬레이션 시작

저장소 루트의 start-demo.cmd를 실행하고 http://127.0.0.1:8000 에 접속한다.
Python 3.12가 필요하다. 첫 실행에 가상환경과 requirements.txt 의존성을 설치한다.
이미 8000번 포트에 서버가 실행 중이면 그 화면을 이용하거나 기존 서버를 종료한다.
종료는 실행한 콘솔에서 Ctrl+C.

모의 데이터는 data/demo.db에 저장한다. 기존 현장 기록용 monitoring.db와 분리된다.
상단 DEMO 배지와 하단 시뮬레이션 패널은 모의 서버에서만 표시된다.
시나리오 재생은 화면 상태를 초기화하지만 완료된 가동·알람 기록은 유지한다.

직접 실행하려면 monitoring-twin 폴더에서:

    .venv\Scripts\python -m pip install --no-cache-dir -r requirements.txt
    $env:MT_SOURCE = "mock"
    $env:MT_DB = "data/demo.db"
    .venv\Scripts\python -m uvicorn server.main:app --host 127.0.0.1 --port 8000

## 화면

- 라인 모니터: 3D 정면·탑 뷰·입체 시점, 라벨 표시, 공정 5구간, 로봇 상태, 알람.
- 생산 통계: 기간별 생산·불량·공정 시간·목표 달성 상태.
- 가동 기록: 합격/불합격 필터, 가동 상세, 알람 이력, CSV/ZIP 내보내기.
- 시뮬레이션: 정상 조립, 로봇1 오류, 비상정지·복구, 통신 끊김·복구. 0.5/1/2/5/10배속, 재생 중 속도 변경, 일시정지·재개, 반복 재생.
- 비상정지·일시정지 및 서버/게이트웨이/PLC 통신 끊김에는 모의 이동을 멈춘다.
  로봇 개별 연결 끊김에도 해당 로봇의 마지막 자세를 유지한다.

## 구조와 한계

mock/scenarios → mock/player.py → server/main.py → server/snapshot.py
→ WebSocket /ws → client/main.js → 상태 패널 + client/twin3d.js.

server/store.py는 SQLite 기록과 KPI를 계산한다.
3D 설비 원본은 ../web/assets, 로봇은 Indy7 URDF/STL을 공유한다.
로봇은 조립·용접·분류별 경로를 따라 가감속하며 작업 단계를 표시한다. ST 버튼으로 작업을 확대한다.
팔레트 이동, 부품 안착, 분류 운반, 보관 승강기 동작을 순서에 맞춰 연결한다.
동작은 작업 상태 기반 시각화다. 실제 설비 좌표를 목표로 역기구학을 계산하고, STL 링크 외접 상자와 GLB 설비 삼각형의 간섭을 검사한다. 실제 관절각 동기화는 구현 전이다.
반복 시 현재 라인·트레이·보관 상태는 초기화하고 완료 기록은 유지한다.
모의 일시정지 시간은 로봇 작업 시간에서 제외한다. 기록 시각과 사이클 시간은 실제 시계 기준이다.
전차는 단계별 간이 형상이다. 실제 게이트웨이 연결과 현장 검증은 기존 계획의 M4 이후 작업이다.
웹에서 실물 PLC·로봇에 명령을 보내는 기능은 없다.

## 모델 기반 경로 검사 (2026-10-02)

- 작업 경로 버튼: 로봇 끝단의 검사된 예정 경로 표시. ST 버튼: 해당 로봇 작업 확대.
- 조립·용접·분류 목표는 Zone/Tray 노드에서 읽는다. 카메라 간섭 시 접근 방향과 상승·선회 경유점을 탐색한다.
- 설비 삼각형 BVH, 로봇 링크 OBB, 비인접 링크 자기 간섭, 다른 로봇, 이동 팔레트·제품을 검사한다.
- 로봇3는 운반 제품의 외접 부피도 검사하며 제품이 끝단을 따른다. 트레이 위에서 분리한 뒤 짧게 안착한다.
- 실행 중 경로를 세분해 검사하고 간섭 예상 시 해당 팔 또는 팔레트 이송을 보류한다. 정지 후에는 정지 속도에서 다시 가속한다.
- manifest의 motion.clearance_m=0.012는 시각화용 여유 가정이다. joint_limits의 속도·가속도는 시뮬레이션 시간 기준이며 배속에 비례한다.
- 고정 베이스/받침대, 인접 관절 하우징, 집는 제품/툴의 의도적 접촉은 제외한다. 외접 상자와 이산 경로 검사이므로 보수적인 오탐 및 표본 사이 간섭 가능성이 있다. 물리 접촉 해석이나 현장 안전 인증이 아니다.
- 회피 경로를 찾지 못하면 이동 보류를 표시한다. 서버의 공정 이벤트·기록은 원래 시간대로 계속되며, 화면 동작을 맞추려고 장비 데이터나 명령을 수정하지 않는다.

검증 명령 (monitoring-twin 폴더):

    node --experimental-loader ./tests/three-loader.mjs --test tests/collision.test.mjs tests/motion.test.mjs tests/pallets.test.mjs

동작 테스트 23개: 실제 GLB/STL/URDF로 5개 작업 및 합격·불합격 트레이 3칸의 경로/복귀를 120 Hz로 검사한다. 기존 ST2 카메라 충돌 재현, 회피 경유, 동적 간섭, 관절 범위, 속도/가속도, 운반 동기화와 이송 보류를 포함한다.

## 화면 조작과 자세 확인

- 집중 모드: 3D 화면을 창 전체로 확장한다. F로 전환하고 Esc로 닫는다. 배경 조작 요소는 집중 모드 동안 키보드 탐색에서 제외한다.
- 작업 따라가기: BUSY 로봇으로 카메라와 관절 패널을 전환한다. 수동 시점 전환·드래그·ST 선택 시 자동 추적을 해제한다.
- 화면 상단 작업 카드: 현재 3D 동작 단계와 경로 진행률. 서버 공정 시간과 별개인 화면 애니메이션 진행률이다.
- JOINT MONITOR: 선택한 ST의 6개 모의 관절각과 관절 범위 표시. 실물 로봇 측정값이 아니다.
- 1/2/3: 정면/탑 뷰/입체. Space: 모의 재생 정지·재개. 입력창에서는 단축키를 실행하지 않는다.
- 화면은 작은 너비에서 세로 배치하고, 바닥 격자와 흐름 방향선으로 설비 배치를 읽기 쉽게 표시한다.

## 로봇 표면 디테일

- Indy7 원본 STL 좌표와 법선을 유지하면서 도장, 관절 실링, 금속 캡, 손목 플랜지의 색·금속도·거칠기를 구분한다.
- 관절 캡의 체결 볼트는 인스턴싱으로 표시하고, 베이스에 스테이션별 명판을 표시한다.
- 추가 볼트가 기존 12 mm 링크 검사 범위 안에 들어가는지 실제 STL로 검증한다.
- 검증: 외형 보존·볼트 범위와 기존 동작·충돌 검사를 포함한 Node 테스트 25개 통과.

    node --experimental-loader ./tests/three-loader.mjs --test tests/robot-finish.test.mjs tests/collision.test.mjs tests/motion.test.mjs tests/pallets.test.mjs

## 흡착 조립 시연

- 로봇 뒤쪽에 차체·파워팩·포탑을 각각 3개 준비한 선반형 공급대를 표시한다. 사용한 부품만 제거하며 재시작/반복 시 공급대를 초기화한다.
- ST1 차체/파워팩과 ST2 포탑은 공급대 접근 → 패드 하강 → 진공 형성 → 들어올림 → 운반/정렬 → 하강 → 진공 해제 → 후퇴 순서로 표시한다.
- 부품은 흡착 확인 시 TCP에 부착되어 손목 회전을 따르고, 해제 후 팔레트 부품으로 전환된다. 서버의 단계 이벤트가 먼저 도착해도 중복 표시하지 않는다.
- 흡착 대기 시간, 운반 중 정지/재개, 후속 작업 대기와 조립 중 팔레트 이송 보류를 지원한다. 정상 시나리오의 각 조립 작업은 14초로 늘렸다.
- 공급대·선반, 운반 부품과 툴을 경로 검사에 포함한다. 선택한 공급 선반과의 받침 접촉, 대상 팔레트와의 조립 접촉만 부품/툴 검사에서 허용한다. 링크 검사는 유지한다.
- 공급대 치수·105 mm 흡착 툴·진공 확인 시간은 시연용 가정이다. 압력/하중/흡착 성공 여부를 계산하는 물리 해석이나 실물 제어는 아니다. 이벤트 규격은 유지한다.

    node --experimental-loader ./tests/three-loader.mjs --test tests/assembly.test.mjs tests/collision.test.mjs tests/motion.test.mjs tests/pallets.test.mjs tests/robot-finish.test.mjs

## 작업 완료와 이송 연동

- 모든 로봇의 작업·용접·복귀·대기 경로가 끝나야 컨베이어가 출발한다. 간섭 보류 중에는 출발하지 않는다.
- 다음 작업/팔레트 이동 스냅샷은 화면 순서 큐에 보관한다. 앞 작업과 팔레트 도착을 확인한 다음 적용해 고배속에서도 중간 공정을 건너뛰거나 진행 중 경로를 덮어쓰지 않는다.
- 모의 데이터 모드의 로봇 카드/공정 표시도 화면에 적용된 순서를 따른다. 연결 끊김·오류·비상정지 입력은 최신 수신값으로 즉시 정지한다. 서버 기록/통계/시나리오 시계는 원래 값을 유지한다.
- 이송 정지와 제품의 흡착 추종/트레이 안착은 별도로 갱신한다. 다른 탭에서 돌아왔을 때 관절을 대기 자세로 초기화하지 않는다.
- ST2 용접 목표에 흡착 툴 길이를 반영하고 툴 형상을 조립 외 동작/복귀 검사에도 포함한다. 관절 속도 75°/s, 가속도 180°/s²는 시연용 제한이다.
- 비상정지 해제 후 STOP 상태에서는 RUN을 기다린다. 모의 시나리오가 끝난 뒤 남은 화면 동작은 순서대로 마무리한다.
